# beast-ux-terminal-luxe

# BEAST-UX Protocol: Terminal-Luxe Design Intelligence

Guía maestra de diseño paramétrico e interfaces de alto rendimiento. Esta herramienta no crea "webs bonitas"; forja infraestructuras digitales precisas, autoritarias y libres de ruido visual. 

## Criterios de Invocación (Must Use)

- Diseño de interfaces cerradas (*Walled Gardens*), bóvedas de datos o plataformas de verificación.
- Implementación de arquitecturas visuales basadas en *Raw Data* (coordenadas, métricas, hashes).
- Refactorización de componentes para eliminar "ruido corporativo" (sombras suaves, bordes redondeados excesivos).
- Desarrollo de micro-interacciones mecánicas y sistemas de *Progressive Disclosure*.

## Reglas de Arquitectura Visual (Prioridad Absoluta)

### 1. Estética y Geometría (CRITICAL)
- `pure-contrast` - Fondos oscuros absolutos (ej. `#000000` o `#050505`). Superficies delimitadas por líneas de 1px, no por sombras.
- `sharp-edges` - Cero radios de borde (`border-radius: 0`) o radios matemáticamente ínfimos (`2px` máximo para botones críticos). Todo es un bloque, un panel o un lienzo.
- `terminal-accent` - Uso monocromático predominantemente. Un solo color de acento eléctrico (ej. verde fósforo, naranja industrial) usado exclusivamente para estados de éxito o llamadas a la acción vitales.
- `no-emoji` - Prohibido el uso de emojis. Reemplazar exclusivamente con vectores geométricos puros, glifos técnicos o iconografía SVG minimalista.

### 2. Tipografía y Datos (HIGH)
- `dual-typography` - Combinación estricta: Fuentes monoespaciadas (Monospace) agresivas para métricas, UI y *raw data* + fuentes Serif de alta costura o Sans-Serif monolíticas para los títulos editoriales.
- `data-exposure` - Exponer visualmente la "metadata" (peso, tiempo, coordenadas) como parte de la estética de la interfaz.
- `anti-truncation` - Los datos técnicos nunca se truncan. Deben romper la línea o habilitar un flujo de lectura claro.

### 3. Interacción y Movimiento (HIGH)
- `mechanical-easing` - Animaciones ultra-rápidas (100ms - 150ms). Curvas de aceleración tipo "snap" (ej. `cubic-bezier(0.1, 0.9, 0.2, 1)`). Las interfaces no flotan, encajan de golpe como hardware físico.
- `intentional-friction` - Requiere acciones físicas claras para revelar información profunda (mantener presionado, *swipe* prolongado, ingresar un *prompt*).
- `haptic-sync` - Todo cambio de estado visual crítico debe estar emparejado mentalmente con una respuesta táctil del sistema.

### 4. Rendimiento y Accesibilidad (CRITICAL)
- `zero-layout-shift` - Precisión matemática en los contenedores. Ningún elemento debe desplazar a otro durante la carga (CLS = 0).
- `contrast-4.5` - Cumplimiento implacable de la regla 4.5:1 para texto normal y 3:1 para grandes titulares. Sin excusas.
- `focus-authority` - Estados de *focus* visibles, rígidos y técnicos (anillos de 2px sólidos y contrastantes), nunca difuminados.

## Anti-Patrones a Destruir
- Degradados suaves, *Glassmorphism* y desenfoques (*blur*) decorativos.
- Diseños condescendientes, "verdes ecológicos" corporativos o ilustraciones amigables.
- Tiempos de animación superiores a 300ms.
- Menús hamburguesa sobrecargados; preferir jerarquías de un solo nivel o interfaces tipo *Command Line*.

## Protocolo de Ejecución Analítica
1. Analizar profundamente la función del componente antes de escribir una línea de código.
2. Eliminar cualquier capa visual que no cumpla una función estructural o narrativa directa.
3. Generar código limpio, fuertemente tipado (TypeScript) y listo para despliegue.
